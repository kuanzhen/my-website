## Purpose

定义站点项目展示区的内容结构、卡片网格布局、每张卡片承载的四项信息（截图 / 名称 / 简介 / GitHub 链接）、悬浮微特效、图片懒加载与主题适配行为，使访客在首屏之后能直接浏览站主的项目作品，并在窄屏、两套主题与资源加载失败等受限环境下保持可读可用。

## ADDED Requirements

### Requirement: 项目展示区占据 `#projects` 锚点并至少展示四个项目

页面 SHALL 在 Hero 之后提供真实的项目展示区，其 `id` 为 `projects`，并取代原来的「内容待补充」占位 section。该区域 MUST 展示不少于 4 个项目卡片，并 MUST 以「项目」作为区域标题，标题层级 MUST 为 `h2`（页面唯一的 `h1` 仍属于 Hero 的姓名）。

#### Scenario: 正常渲染项目展示区

- **GIVEN** 访客打开站点首页
- **WHEN** 访客滚动到 `#projects` 区域
- **THEN** 可见「项目」标题与不少于 4 张项目卡片
- **AND** 该区域不再出现「内容待补充」文案，也不再呈现为占位 section

#### Scenario: 导航与 CTA 都能定位到项目展示区

- **GIVEN** 项目展示区已渲染
- **WHEN** 访客通过导航「项目」链接或 Hero 的「我的项目」CTA 跳转
- **THEN** 页面停在该区域，区域标题完整可见且不被固定导航栏遮挡
- **AND** 页面中 `projects` 这个 id 只对应这一个 section

#### Scenario: 320px 窄屏下不横向溢出

- **GIVEN** 视口宽度为 320px
- **WHEN** 项目展示区渲染完成
- **THEN** 卡片按单列纵向排列，不出现横向滚动条
- **AND** 卡片内的名称、简介与 GitHub 链接均完整可见

### Requirement: 项目卡片包含截图、名称、简介与 GitHub 链接四项内容

每张项目卡片 SHALL 同时展示四项内容：项目截图、项目名称、项目简介（站主对项目的见解）以及指向该项目 GitHub 仓库的链接。项目名称 MUST 使用卡片内的标题元素（非 `h1`），项目截图 MUST 提供描述该项目画面的替代文本。

#### Scenario: 正常渲染一张项目卡片

- **GIVEN** 站点已配置至少 4 个项目数据
- **WHEN** 访客查看任意一张项目卡片
- **THEN** 卡片内同时可见该项目截图、名称、简介与 GitHub 链接
- **AND** 截图替代文本与项目名称一致可辨识

#### Scenario: 长名称与长简介的折行

- **GIVEN** 某个项目的名称或简介长度明显超过卡片一行可容纳的宽度
- **WHEN** 卡片在窄屏下渲染
- **THEN** 文本按词边界折行，不溢出卡片、不被截断
- **AND** 同一卡片内的 GitHub 链接仍完整可见可点击

### Requirement: 项目卡片采用响应式网格布局

项目卡片 SHALL 以网格方式排列：窄屏单列，宽屏多列。网格 MUST 随视口宽度自适应，不得依赖横向滚动查看其余卡片。

#### Scenario: 宽屏下同排展示多张卡片

- **GIVEN** 视口宽度为 1280px
- **WHEN** 项目展示区渲染完成
- **THEN** 同一行内并排出现多张项目卡片
- **AND** 卡片之间留有一致的间距

#### Scenario: 平板宽度下自动减少列数

- **GIVEN** 视口宽度处于桌面与手机之间的中间宽度（如 768px）
- **WHEN** 项目展示区渲染完成
- **THEN** 卡片列数介于窄屏单列与宽屏多列之间
- **AND** 不出现卡片被压到无法阅读的宽度

### Requirement: 卡片悬浮时呈现轻微抬升与强调

指针悬浮在项目卡片上时，卡片 SHALL 呈现轻微抬升，并同时以边框或阴影强化卡片轮廓，作为可查看项目的视觉反馈；指针移出后 MUST 恢复原状。该微特效只作用于项目卡片，不得波及 Hero 的粒子层。访客启用「减弱动态效果」偏好时，MUST NOT 出现位移或缩放，但仍需可见的边框或阴影强调。

#### Scenario: 鼠标悬浮卡片

- **GIVEN** 访客使用指针设备位于项目展示区
- **WHEN** 指针移入某张项目卡片
- **THEN** 该卡片轻微抬升，边框或阴影强调明显强于未悬浮状态
- **AND** 其余卡片保持原状

#### Scenario: 指针移出后恢复

- **GIVEN** 某张项目卡片正处于悬浮状态
- **WHEN** 指针移出该卡片
- **THEN** 卡片回到原始位置与原始轮廓

#### Scenario: 减弱动效下的悬浮强调

- **GIVEN** 访客启用了「减弱动态效果」偏好
- **WHEN** 指针移入项目卡片
- **THEN** 卡片不产生位移或缩放
- **AND** 边框或阴影的强调仍然可见

### Requirement: 项目截图懒加载并处理加载失败

项目截图 MUST 使用懒加载，未进入视口前不得请求图片资源，以保证首屏不被项目截图阻塞。截图加载失败时，卡片 MUST 仍保留可读的项目名称与简介，不出现破图图标或空白塌陷。

#### Scenario: 首屏不请求项目截图

- **GIVEN** 访客刚打开站点并停留在 Hero 首屏
- **WHEN** 项目展示区尚未进入视口
- **THEN** 项目截图资源尚未被请求
- **AND** 首屏文本与 CTA 正常呈现，不等待截图加载

#### Scenario: 滚动接近项目区时按需加载

- **GIVEN** 访客向下滚动接近项目展示区
- **WHEN** 卡片进入浏览器设定的懒加载范围
- **THEN** 对应截图开始加载并逐步呈现
- **AND** 加载过程中卡片布局不发生明显跳动

#### Scenario: 截图加载失败

- **GIVEN** 某张项目截图的地址失效或网络请求失败
- **WHEN** 卡片渲染完成
- **THEN** 卡片仍显示项目名称、简介与 GitHub 链接
- **AND** 不出现浏览器的破图图标或高度塌陷的空白区域

### Requirement: 项目卡片在两套主题下保持可读

卡片底色、边框、名称、简介与 GitHub 链接 MUST 沿用站点现有主题 token 随亮/暗主题切换，不得使用硬编码颜色。亮色与暗色主题下，正文与次要文字的对比度 MUST 不低于 4.5:1。

#### Scenario: 亮色主题下的卡片

- **GIVEN** 站点处于亮色主题
- **WHEN** 访客查看项目卡片
- **THEN** 卡片与页面背景之间边界清晰，不出现突兀色块
- **AND** 名称、简介与链接文字对比度均不低于 4.5:1

#### Scenario: 暗色主题下的卡片

- **GIVEN** 站点处于暗色主题
- **WHEN** 访客查看项目卡片
- **THEN** 卡片底色与边框同样切换为暗色方案
- **AND** 名称、简介与链接文字对比度均不低于 4.5:1

#### Scenario: 切换主题时卡片同步更新

- **GIVEN** 访客正停留在项目展示区
- **WHEN** 访客切换亮/暗主题
- **THEN** 所有卡片立即切换到对应主题配色
- **AND** 不出现部分卡片残留旧配色的情况

### Requirement: GitHub 链接在新标签页打开

每张项目卡片 SHALL 提供一个指向该项目 GitHub 仓库的外链，该链接 MUST 在新标签页打开，并带 `rel="noopener noreferrer"`，且 MUST 让辅助技术知道它将在新标签页打开。项目数据未提供有效地址时，MUST NOT 渲染指向空地址、`#` 或占位域名的死链。

#### Scenario: 正常点击 GitHub 链接

- **GIVEN** 某张项目卡片已配置 GitHub 仓库地址
- **WHEN** 访客点击该卡片的 GitHub 链接
- **THEN** 浏览器在新标签页打开该仓库页面
- **AND** 当前页面停留在项目展示区，不发生跳转或滚动

#### Scenario: 用键盘触达 GitHub 链接

- **GIVEN** 访客只使用键盘操作
- **WHEN** 访客按 Tab 依次移动焦点至某张卡片的 GitHub 链接
- **THEN** 焦点指示清晰可见
- **AND** 按 Enter 可在新标签页打开该仓库

#### Scenario: 未配置有效链接

- **GIVEN** 某个项目数据中的 GitHub 地址为空或非法
- **WHEN** 卡片渲染完成
- **THEN** 卡片不呈现可点击的 GitHub 链接
- **AND** 页面上不存在 `href="#"`、空地址或占位域名的死链
