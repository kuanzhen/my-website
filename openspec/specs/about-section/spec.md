# about-section Specification

## Purpose

定义站点末尾「关于我」区域的内容结构与布局、站主照片的加载与降级、三段个人简介的可读性，以及纯文本品牌标签「混血哲谈」的展示方式，使访客在浏览完项目与联系信息后能认识站主本人及其品牌，并在窄屏与两套主题下保持完整可读。

## Requirements

### Requirement: 关于我区域位于页面末尾并占据 `#about` 锚点

页面 SHALL 在联系我占位 section 之后提供「关于我」区域，其 `id` 为 `about`，且 MUST 是页面最后一个 section。该区域 MUST 以「关于我」作为标题，标题层级 MUST 为 `h2`（页面唯一的 `h1` 仍属于 Hero 的姓名）。导航「关于」链接 MUST 能定位到该区域。

#### Scenario: 页面顺序以关于我收尾

- **GIVEN** 页面已渲染完成
- **WHEN** 访客从首页向下滚动到页面底部
- **THEN** 页面 section 顺序依次为 Hero、项目、联系我、关于我
- **AND** 关于我之后不再有其他 section

#### Scenario: 导航「关于」定位到区域

- **GIVEN** 关于我区域已渲染
- **WHEN** 访客点击导航栏「关于」
- **THEN** 页面停在 `#about` 区域
- **AND** 「关于我」标题完整可见且不被固定导航栏遮挡
- **AND** 页面中 `about` 这个 id 只对应这一个 section

#### Scenario: 320px 窄屏下不横向溢出

- **GIVEN** 视口宽度为 320px
- **WHEN** 关于我区域渲染完成
- **THEN** 照片、三段简介与品牌标签均完整可见
- **AND** 页面不出现横向滚动条

### Requirement: 照片与三段简介采用左右布局并在窄屏堆叠

在宽屏下，关于我区域 SHALL 将站主照片置于左侧、三段个人简介置于右侧；在窄屏下 MUST 改为纵向堆叠（照片在上、简介在下），任何宽度下都不得出现横向溢出或内容裁切。三段简介 MUST 全部完整呈现，不得截断或折叠。

#### Scenario: 宽屏下的左右布局

- **GIVEN** 视口宽度为 1280px
- **WHEN** 关于我区域渲染完成
- **THEN** 照片位于左侧、三段简介位于右侧，处于同一水平排列中
- **AND** 照片与简介之间留有清晰间距，不互相重叠

#### Scenario: 窄屏下的纵向堆叠

- **GIVEN** 视口宽度为 320px
- **WHEN** 关于我区域渲染完成
- **THEN** 照片显示在简介上方，二者纵向排列
- **AND** 三段简介按顺序完整显示，不出现截断、折叠或横向溢出

#### Scenario: 三段简介完整呈现

- **GIVEN** 站点已配置三段个人简介
- **WHEN** 关于我区域渲染完成
- **THEN** 三段文字均按顺序可见
- **AND** 不存在「展开更多」等需要额外交互才能阅读的隐藏内容

### Requirement: 站主照片使用懒加载并固定宽高比

站主照片 MUST 使用懒加载，未进入视口前不得请求图片资源。照片容器 MUST 预留固定宽高比，使照片加载前后页面布局不发生跳动。照片 MUST 提供描述站主的可读替代文本；加载失败时 MUST 保留容器与简介内容，不出现破图图标或布局塌陷。

#### Scenario: 未滚动到关于我时不请求照片

- **GIVEN** 访客刚打开站点并停留在 Hero 首屏
- **WHEN** 关于我区域尚未进入视口
- **THEN** 站主照片资源尚未被请求
- **AND** 首屏内容正常呈现，不等待照片加载

#### Scenario: 滚动接近关于我时加载照片

- **GIVEN** 访客向下滚动接近关于我区域
- **WHEN** 照片进入浏览器设定的懒加载范围
- **THEN** 照片开始加载并呈现
- **AND** 加载过程中照片容器尺寸保持不变，简介文字不位移

#### Scenario: 照片加载失败

- **GIVEN** 站主照片的地址失效或网络请求失败
- **WHEN** 关于我区域渲染完成
- **THEN** 照片容器仍保持占位，三段简介与品牌标签正常显示
- **AND** 不出现浏览器的破图图标或高度塌陷

### Requirement: 区域下方展示纯文本品牌标签

关于我区域 SHALL 在照片与简介下方展示品牌标签「混血哲谈」。该标签 MUST 为纯文本展示元素，MUST NOT 是可点击链接或按钮，MUST NOT 可被键盘聚焦，也不得暗含跳转行为。标签在两套主题下 MUST 保持可读。

#### Scenario: 品牌标签正常展示

- **GIVEN** 关于我区域渲染完成
- **WHEN** 访客查看照片与简介下方
- **THEN** 可见文本「混血哲谈」
- **AND** 该标签位于照片与简介之后，独立成行或独立徽标区域

#### Scenario: 品牌标签不可点击

- **GIVEN** 访客使用鼠标或键盘操作
- **WHEN** 访客尝试点击品牌标签或按 Tab 移动焦点
- **THEN** 标签不触发任何跳转或动作
- **AND** 焦点不会停留在品牌标签上

#### Scenario: 屏幕阅读器读取品牌标签

- **GIVEN** 访客使用屏幕阅读器
- **WHEN** 屏幕阅读器读到品牌标签
- **THEN** 该标签被读作普通文本「混血哲谈」
- **AND** 不会被宣布为链接或按钮

### Requirement: 关于我区域在两套主题下保持可读

照片容器、简介文字与品牌标签 MUST 沿用站点现有主题 token 随亮/暗主题切换，不得使用硬编码颜色。亮色与暗色主题下，正文文字的对比度 MUST 不低于 4.5:1，品牌标签的文字与底色对比度 MUST 不低于 4.5:1。

#### Scenario: 亮色主题下的关于我

- **GIVEN** 站点处于亮色主题
- **WHEN** 访客查看关于我区域
- **THEN** 照片容器、简介与品牌标签与页面整体配色一致
- **AND** 简介文字与品牌标签的对比度均不低于 4.5:1

#### Scenario: 暗色主题下的关于我

- **GIVEN** 站点处于暗色主题
- **WHEN** 访客查看关于我区域
- **THEN** 照片容器、简介与品牌标签切换为暗色方案
- **AND** 简介文字与品牌标签的对比度均不低于 4.5:1

#### Scenario: 切换主题时区域同步更新

- **GIVEN** 访客正停留在关于我区域
- **WHEN** 访客切换亮/暗主题
- **THEN** 照片容器、三段简介与品牌标签立即切换到对应主题配色
- **AND** 不出现局部残留旧配色的情况
